# Data Model: 주문 생성 시 레슨 할인 자동 적용

이 피처는 신규 Entity/Domain/DTO를 추가하지 않는다.
기존 클래스의 로직을 변경하여 할인 선별 기능을 구현한다.

## 변경 대상

### CreateOrderService (수정)

`com.latinhouse.api.order.application.service.CreateOrderService`

**추가되는 로직**:

1. `findProfilePort.findById(profileId)` 반환값에서 Profile 객체를 보존한다.
2. `lesson.getDiscounts()`를 순회하여 적용 가능한 할인을 필터링한다.
3. 필터링된 LessonDiscount 목록을 OrderDiscount 리스트로 변환하여 Order에 설정한다.

**할인 선별 규칙**:

| LessonDiscount.type | 선별 조건 |
|---------------------|-----------|
| SEX | `discount.getCondition().equals(profile.getSex().name())` — Profile.sex가 null이면 제외 |
| EARLYBIRD | 전체 EARLYBIRD 중 `condition` 문자열 최솟값 1건만 선택 |

**OrderDiscount 매핑**:

```
OrderDiscount {
  id         = null (auto-generated by DB)
  orderId    = order.getId()  (저장 후 JPA가 연결)
  discountType = OrderDiscountType.LESSON
  discountId = lessonDiscount.getId()
  amount     = lessonDiscount.getAmount()
}
```

## 재사용 도메인/클래스

| 클래스 | 패키지 | 역할 |
|--------|--------|------|
| `LessonDiscount` | `lesson.domain` | 레슨 할인 소스 — type, condition, amount, id |
| `DiscountType` | `lesson.domain` | SEX("S") / EARLYBIRD("E") 구분 |
| `Profile` | `profile.domain` | 구매자 성별(sex) 조회 |
| `Sex` | `profile.domain` | M / F enum |
| `OrderDiscount` | `order.domain` | 주문 할인 기록 객체 |
| `OrderDiscountType` | `order.domain` | LESSON / COUPON |

## 테스트 변경

### CreateOrderServiceTest (수정)

기존 테스트 시나리오는 유지하며 아래 케이스를 추가한다.

| 테스트 메서드 | 검증 내용 |
|---------------|-----------|
| `createOrder_sexDiscount_matching_included` | Profile.sex=M, condition=M SEX 할인 → discounts에 포함 |
| `createOrder_sexDiscount_notMatching_excluded` | Profile.sex=F, condition=M SEX 할인 → discounts에 미포함 |
| `createOrder_earlybirdDiscount_earliestSelected` | EARLYBIRD 2건 → condition 최솟값 1건만 포함 |
| `createOrder_mixedDiscounts_bothApplied` | SEX 일치 + EARLYBIRD 존재 → 2건 모두 포함 |
| `createOrder_noDiscounts_emptyList` | lesson.discounts = [] → order.discounts = [] |
